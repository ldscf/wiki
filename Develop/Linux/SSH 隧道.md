SSH 隧道（SSH Tunneling），也称 SSH 端口转发，是 SSH 协议中极具威力的功能。它通过加密的 SSH 连接传输其他网络协议的数据，常用于安全通信、绕过防火墙限制以及访问内网服务。

SSH 隧道主要有三种工作模式：

| 模式 | 说明 | 命令参数 | 方向 | 核心用途 | 备注 |
| 本地转发 | 将本地端口映射到远程主机端口 | -L | 本地 -> 远程网络 | 访问远程内网服务 | 能访问本地转发主机即可访问 |
| 远程转发 | 将远程主机端口映射到本地端口（反向隧道） | -R | 远程 -> 本地网络 | 将本地服务暴露给外网，常用于内网穿透 | 能访问外网主机即可访问所转发的内网主机 |
| 动态转发 | 建立 SOCKS5 代理 | -D | 本地 -> 任意 | 创建加密代理，全局流量转发 |

### 核心参数说明
```
  *-C 数据压缩
  -f 后台操作，只有当提示用户名密码的时候才转向前台
  -N 不执行远端命令，不打开交互式 Shell，只是端口转发的纯隧道时使用
  -g 允许远端主机连接本地转发端口。现代更常用：0.0.0.0:端口 或 内网IP:端口
  -T 不分配伪终端（TTY）*
```

### 本地端口转发（-L）

这是最常用的一种模式。
- 功能：将本地计算机的某个端口，映射到远程网络中的另一台机器的某个端口。
- 场景：无法直接访问公司内网的数据库服务器（10.0.0.11:3306），但可以通过 SSH 登录到一台跳板机（abc.com）。这时，就可以在本地和跳板机之间建立一条隧道，通过访问本地的某个端口（如 localhost:33306）来间接访问内网的数据库。
```
 # ssh -L [本地地址:]本地端口:目标主机:目标端口 用户名@跳板机
 # 本地地址若省略，则只能在本机使用。0.0.0.0 或为空监听所有网络接口
 # 以下命令通过本地计算机的 33306 端口，通过 abc.com 转发访问数据库服务器（10.0.0.11:3306）
 ssh -C -f -N -g -L  33306:10.0.0.11:3306 user@abc.com
```
- 数据流向：
1. 访问本地 localhost:33306
1. 本地 SSH 拦截流量，通过加密的 SSH 隧道发送给 abc.com
1. abc.com 上的 SSH 服务端解密数据，然后将其转发给内网目标 10.0.0.11:3306

### 远程端口转发（-R）

这种模式与本地端口转发方向相反，故也习惯称为反向隧道。
- 功能：将远程服务器的某个端口，映射到本地网络中的一台机器的某个端口（远程端口转发主机需要能同时访问远程服务器和本地网络主机）。
- 场景：有在不同网段的机器 C 和 T，T 无公网 IP，此时 C 无法向 T 发起连接。此时需要一台拥有公网 IP 的服务器（P）作为中转。 外网机器 C 通过跳板机（如 abc.com:38080）以及内网主机（T 或与 T 同网段，可以 SSH 到跳板机）的远程端口映射，访问内网 T 主机应用（如 10.0.0.11:8080）
```
 # ssh -R [远程绑定地址:]远程端口:目标主机:目标端口 用户名@SSH服务器
 # T 主机
 ssh -C -f -N -g -R :38080:127.0.0.1:8080 user@abc.com
 # 与 T 同网段主机
 ssh -C -f -N -g -R :38080:10.0.0.11:8080 user@abc.com
```
- 数据流向：
1. 外网机器访问 http://abc.com:38080
1. abc.com 上的 SSH 拦截流量，通过加密的 SSH 隧道发送回内网 SSH 客户端（执行命令的主机）
1. SSH 客户端将数据转发到 10.0.0.11:8080

#### 服务器端必要配置

中转服务器（P）需要打开 TCP 转发。
 ```

# /etc/ssh/sshd_config

# 允许远程转发监听非回环地址（否则转发端口仅限服务器本机访问）
GatewayPorts yes

# 允许 TCP 转发
AllowTcpForwarding yes
```

### 动态端口转发（-D）

这种模式创建了一个本地的 SOCKS 代理服务器，允许将各种连接通过 SSH 隧道转发出去。
- 功能：通过动态端口转发，可以将所有流量导向可信任的远程服务器
- 场景：在一个不安全的公共 Wi-Fi 上，希望所有的网络流量都被加密，或者希望绕过本地网络对某些网站的限制

在后台静默运行（-f）一个 SSH 连接，不打开远程 shell（-N），只建立加密隧道，在本地 1080 端口（-D）开启 SOCKS5 代理服务，所有通过这个代理的流量都会通过 user@abc.com 服务器转发出去（-g），并在传输过程中进行压缩（-C）。
```
 # ssh -C -f -N -g -D [本地绑定地址:]本地端口 用户名@SSH服务器
 ssh -C -f -N -g -D 1080 user@abc.com
```

**数据流向**
1. 浏览器访问 google.com
1. 浏览器发现系统设置了 SOCKS 代理（127.0.0.1:1080），于是将请求发送到本地的 1080 端口
1. SSH 客户端接收到请求，通过加密的 SSH 隧道发送给 abc.com
1. abc.com 上的 SSH 服务端解密数据，去访问 google.com，然后将获取的结果通过隧道加密返回

**测试**
```
 # 使用 -v 参数查看详细信息
 curl -v --socks5 127.0.0.1:1080 http://httpbin.org/ip
```

### Example

#### 连接保持
1. 网络设备超时：防火墙/NAT 设备通常会在 5-30 分钟无流量后清除会话
1. SSH 服务端超时：服务端默认配置可能断开空闲连接
 ```

# 在命令行中增加参数：-o ServerAliveInterval=60 -o ServerAliveCountMax=3 ...

# 或者 .ssh/config
Host *
    ServerAliveInterval 60      # 每60秒发一次心跳
    ServerAliveCountMax 3       # 连续3次心跳失败就断开
    TCPKeepAlive yes            # 保持 TCP 连接活跃
    ExitOnForwardFailure yes    # 只要转发失败就立即报错退出
    ConnectTimeout 10           # 连接超时时间（秒）
```
- ServerAliveInterval: 发送的是经过 SSH 加密后的普通数据包。在防火墙看来，这和你在输入命令或传输文件的流量完全没有区别。
- TCPKeepAlive: 发送的是不带载荷（Payload）的裸 ACK 包。对于某些具有深度包检测（DPI）能力的防火墙来说，这种有规律的、无数据的探测包是非常明显的“心跳特征”。

#### 绑定到多个内网 IP
 ```

# 只有指定的两个 IP 才能连接到代理
ssh -f -N \
    -D 192.168.0.10:1080 \
    -D 192.168.0.20:1080 \
    user@abc.com
```

#### 开启多个不同的隧道
 ```

# 只有本机才能连接到代理，开放访问 33306、33389 端口

# 要求：abc.com 服务器：必须能够“看”到并访问 10.0.0.11/12

# ExitOnForwardFailure=yes 只要有一个转发失败，立即报错退出
ssh -C -f -N \
    -L 0.0.0.0:33306:10.0.0.11:3306 \
    -L 0.0.0.0:33389:10.0.0.12:3389 \
    -D 127.0.0.1:1080 \
    user@abc.com
```

#### 使用 Config 文件
 ```

# ssh -f -N my_tunnel
Host my_tunnel
    HostName abc.com
    User user
    DynamicForward 127.0.0.1:1080
    LocalForward 0.0.0.0:33306 10.0.0.11:3306
    LocalForward 0.0.0.0:33389 10.0.0.12:3389
```
