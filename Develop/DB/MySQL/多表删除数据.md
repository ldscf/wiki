MySQL 可以在一条语句中同时从多张表中删除数据。

不同数据库系统对多表删除（Multi-table DELETE）的语法和底层功能支持存在较大差异：

***支持**：如 MySQL、MariaDB

***支持“连接筛选”**：如 SQL Server、PostgreSQL

***不支持**：如 Oracle、SQLite

### 语法

在 MySQL 中，通过 JOIN 连接多张表，并在 DELETE 关键字后列出所有需要被清理数据的目标表别名。
 ```
DELETE t1, t2 
 FROM table1 t1
 JOIN table2 t2 ON t1.id = t2.t1_id
 WHERE t1.status = 'inactive';
```

***DELETE t1, t2**：显式指定同时删除 t1 和 t2 中符合匹配条件的记录。

***JOIN ... ON ...**：通过关联列建立表间关系。

***WHERE**：作用于连接后的结果集中，满足条件的行都会被对应清除。

### 场景

###### 删除多表数据
 ```
DELETE users, orders 
 FROM users 
 LEFT JOIN orders ON users.id = orders.user_id 
 WHERE users.last_login < '2023-01-01';
```

###### 删除指定表数据

如果只需删除 orders 表中的记录，但过滤条件依赖于 users 表，只需在 DELETE 后保留目标表名：
 ```
DELETE orders 
 FROM orders 
 JOIN users ON orders.user_id = users.id 
 WHERE users.is_banned = 1;
```

### 主流数据库支持情况汇总

| 数据库名称 | 删除多表数据 | 支持 JOIN 条件 | 替代方案 |
|:---|:---|:---|:---|
| **MySQL / MariaDB** | Yes | Yes |
| **Microsoft SQL Server** | Yes | 使用多条 DELETE 语句，或借助 外键级联 |
| **PostgreSQL** | Yes（使用 USING） | 在事务（TRANSACTION）中编写多条 DELETE，或使用外键级联 |
| **Oracle Database** | 使用子查询（WHERE IN / EXISTS）、PL/SQL 存储过程 或外键级联 |
| **SQLite** | 使用子查询或外键级联 |

#### 差异

###### SQL Server

支持在 DELETE 语句中使用 FROM ... JOIN 语法进行跨表条件匹配，但只能删除 DELETE 关键字后指定的单张表数据：
 ```
-- 正确：只删除 t1
 DELETE t1
 FROM Table1 t1
 INNER JOIN Table2 t2 ON t1.id = t2.t1_id
 WHERE t2.status = 'expired';
 
 -- 错误：SQL Server 不支持同时写 DELETE t1, t2
```

###### PostgreSQL

不使用标准的 JOIN 关键字配合 DELETE，而是使用特有的 USING 子句。但也只支持删除单表：
 ```
-- 正确：从 t1 中删除匹配 t2 条件的数据
 DELETE FROM table1 t1
 USING table2 t2
 WHERE t1.id = t2.t1_id AND t2.status = 'inactive';
```

###### Oracle & SQLite

DELETE 语句均不支持 JOIN 或 USING 语法。跨表过滤通常只能依靠子查询：
 ```
DELETE FROM orders 
 WHERE user_id IN (
     SELECT id FROM users WHERE is_banned = 1
 );
```

### 替代方案

#### 1. 外键级联删除

若业务模型具有强主从关联（如用户与订单、文章与评论），最标准的方式是在创建表时声明级联删除外键：
 ```
ALTER TABLE orders 
 ADD CONSTRAINT fk_user 
 FOREIGN KEY (user_id) REFERENCES users(id) 
 ON DELETE CASCADE;
```

设置后，只需对主表执行简单的单表删除，数据库引擎会自动同步清空子表关联数据：
 ```
DELETE FROM users WHERE id = 1001;
```

#### 2. 显式事务控制

在不支持单语句多表删除的数据库（如 PostgreSQL、SQL Server）中，可以利用事务来保证原子性：
 ```
BEGIN TRANSACTION;
 
 DELETE FROM orders WHERE user_id = 1001;
 DELETE FROM users WHERE id = 1001;
 
 COMMIT;
```

#### 3. 常见安全建议

***预先核对**：执行多表删除前，建议先将 DELETE ... 改写为 SELECT * ... 检查将要受影响的数据行。

***别名明确**：显式写明要删除的表别名，避免误删非目标表的数据。
