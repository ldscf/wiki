视频文件由两个主要部分组成：视频编码器和容器格式。

### 视频编码器

视频编码器 (Video Codec) 是用来压缩和解压缩视频数据的算法。原始的视频数据量非常庞大，如果不经过压缩，传输和存储都会非常困难。编码器的作用就是用高效的数学方法将这些数据“打包”变小，然后在播放时再“解包”还原。

主流的视频编码器包括：

#### H.264

H.264 (AVC) / x264 : 兼容性的王者
- 特点： H.264，也被称为 AVC (Advanced Video Coding)，是目前使用最广泛、兼容性最好的视频编码标准。它的实现之一就是开源的 x264 编码器。
- 优势： 几乎所有的设备（智能手机、平板、电脑、智能电视等）、操作系统、浏览器和流媒体平台都支持 H.264 的硬件解码和播放。这意味着用 H.264 编码的视频能在绝大多数地方流畅播放，无需额外的插件或软件。
- 应用： 它是 YouTube、Netflix 等流媒体服务的核心编码格式，也广泛应用于蓝光光盘、高清电视广播以及各种网络视频。

#### H.265

H.265 (HEVC) / x265 : 新一代的高效能选手
- 特点： H.265，也被称为 HEVC (High Efficiency Video Coding)，是 H.264 的继任者，其实现之一是开源的 x265 编码器。
- 优势： 相比 H.264，H.265 能够在相同视频质量下将文件大小进一步缩小约 25%-50%，尤其在 4K 甚至 8K 超高清视频方面，其压缩效率的优势更为明显。
- 挑战： 尽管效率更高，但 H.265 的兼容性不如 H.264。较旧的设备可能不支持硬件解码，导致播放时需要更高的 CPU 资源，甚至出现卡顿。此外，其复杂的专利和许可问题也限制了它的普及速度。
- 应用： 随着 4K 视频的普及，H.265 越来越受到重视，并被一些流媒体平台用于 4K 内容传输。

#### VP9

VP9 : Google 的开源力量
- 特点： VP9 是由 Google 开发的开源、免版税的视频编码格式，旨在与 HEVC 竞争。
- 优势： 它在压缩效率上与 HEVC 相当，甚至在某些情况下表现更好。由于其开源特性，它没有 HEVC 复杂的许可费用问题。
- 应用： 主要用于 YouTube 视频，并受到 Chrome 浏览器和 Android 设备的良好支持。

#### AV1

AV1：未来的希望之星
- 特点： AV1 是由开放媒体联盟 (AOMedia) 开发的免版税视频编码格式，成员包括 Google、Apple、Amazon、Netflix、Meta 等业界巨头。
- 优势： 旨在提供比 HEVC 和 VP9 更高的压缩效率，同时保持开源和免版税。
- 发展： 尽管潜力巨大，但 AV1 的编码和解码目前需要更高的计算能力，因此还在初期发展阶段，尚未大规模普及。

#### TS

TS (MPEG Transport Stream) : 原始的视频数据，标准化的数字容器格式，主要设计目的是用于传输和存储视频、音频以及其他数据，特别是在以下场景中：
- 数字电视广播：TS 是数字广播（如 DVB、ATSC、ISDB）的核心格式，因为它能够将多个视频、音频和其他数据流（比如节目指南、字幕等）复用到一个单一的流中进行传输。
- 流媒体：由于其对错误具有较强的鲁棒性（即使部分数据丢失，也能尽可能地播放），TS 也常用于网络流媒体，尤其是一些直播流。
- 录制设备：一些数字视频录像机 (DVR) 或高清摄像机也可能使用 TS 格式进行录制。

TS 文件的特点：
- 流式传输设计：TS 的设计目标是高效传输，它将数据分割成小的固定大小的数据包（通常为 188 字节），这使得它非常适合在不稳定的网络环境或广播中传输，即使遇到错误，也能最大限度地减少影响。
- 多节目支持：一个 TS 流可以包含多个不同的节目，每个节目又可以包含多个视频、音频轨道以及字幕。
- 容器格式：TS 本身是一个容器格式，就像 .mp4 或 .mkv 一样。它里面封装的视频和音频数据可以使用各种编码器进行压缩，最常见的是 MPEG-2 Video 或 H.264 (AVC) 编码的视频，以及 MPEG-1 Audio Layer II (MP2) 或 AAC 编码的音频。
- 鲁棒性：由于其数据包结构，TS 对于传输中的错误（例如信号中断）具有较好的恢复能力，即使部分数据包丢失，播放器也能跳过损坏的部分继续播放。

一般从数字电视录制、或从某些流媒体服务下载下来的视频时，它们很可能就是 .ts 格式。由于 TS 主要是为了传输而设计，它可能不会是最终观看或编辑的最佳格式（例如，文件可能较大，或者其中的编码器不是最新的）。

因此，经常会使用 FFmpeg 等工具将 TS 文件转码（重新编码）为更普遍、更高效的格式，如 .mp4（使用 H.264 或 H.265 编码），以便于存储、分享或在各种设备上播放。

### 容器格式

容器格式 (Container Format) 就像一个“盒子”，它负责将视频流（由编码器压缩）、音频流（由音频编码器压缩）、字幕、章节信息等多种数据封装在一起，形成一个完整的文件。它并不负责视频的压缩，而是定义了这些不同类型的数据如何被组织和存储。

常见的容器格式包括：

#### MP4

MP4 (.mp4)
- 特点： 最流行和兼容性最好的容器格式之一，基于 QuickTime 文件格式。
- 优势： 支持多种视频（H.264, H.265, MPEG-2 等）和音频编码器（AAC, MP3 等）。它几乎在所有设备和平台上都能播放，并且非常适合网络流媒体。

#### MKV

MKV (.mkv)
- 特点： MKV (Matroska Video) 是一种开源、灵活的容器格式。
- 优势： 强大的功能，支持几乎任何数量的视频、音频、字幕轨道，甚至可以包含章节和菜单。因此，它常用于存储高清电影、电视节目和多语言内容。
- 兼容性： 尽管功能强大，但其兼容性略低于 MP4，在一些较旧或特定的设备上可能需要额外的支持。

#### MOV

MOV (.mov)
- 特点： Apple 开发的 QuickTime 文件格式。
- 优势： 在 Apple 生态系统中（macOS, iOS）具有良好的原生支持，常用于视频编辑和专业制作领域。
- 兼容性： 在非 Apple 平台上的兼容性通常不如 MP4。

#### AVI

AVI (.avi)
- 特点： Microsoft 早期的视频容器格式。
- 优势： 历史悠久，简单直接。
- 劣势： 效率较低，不支持现代编码器的高级特性，也不适合网络流媒体。通常包含未压缩或低压缩的视频，文件巨大。现在已不常用。

#### WMV

WMV (.wmv)
- 特点： Microsoft 开发的专有视频格式。
- 优势： 在 Windows 环境下有良好的支持。
- 劣势： 兼容性有限，主要用于 Windows 平台。
