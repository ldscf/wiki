数字证书（Digital Certificates, 通常称为 X.509 证书）是一种电子文档，它将公钥与实体（个人、组织、服务器等）的身份绑定在一起。它由一个受信任的第三方，即证书颁发机构 (Certificate Authority, CA) 签名。

#### 证书的核心作用

证书解决了非对称加密中的一个关键问题：如何验证公钥的真实性？

当你收到一个公钥时，你如何确定这个公钥确实属于它声称的实体（例如，一个银行网站），而不是某个攻击者伪造的？证书就是为了解决这个“公钥的信任问题”而存在的。

#### 证书包含的主要信息
- 公钥：证书所绑定的实体的公钥
- 主体信息：拥有该公钥的实体的信息，例如：
1. 通用名称 (Common Name, CN)：通常是域名（如 www.example.com）或个人/组织名称
1. 组织 (Organization, O)
1. 组织单位 (Organizational Unit, OU)
1. 城市/地区 (Locality, L)
1. 省/州 (State, S)
1. 国家 (Country, C)
- 颁发者信息：颁发该证书的 CA 的名称和信息
- 有效期：证书的有效起始日期和结束日期
- 签名算法：用于对证书进行数字签名的算法（例如 SHA256withRSA）
- 颁发者数字签名：CA 使用其私钥对整个证书内容（除了签名本身）计算出的数字签名，这是证书信任链的关键

#### 证书的工作原理（信任链）

证书的信任是基于一个“信任链”或“信任路径”构建的。

##### 根证书 (Root Certificate):

根证书是证书信任链的起点。它由一个根 CA（通常是业界知名的、高度安全的机构）自行颁发和签名（自签名）。

所有操作系统和浏览器都预装了一批受信任的根 CA 证书。 这是信任的锚点。

##### 中间证书 (Intermediate Certificate):

为了提高安全性，根 CA 通常不直接颁发用户证书。它们会使用自己的私钥来签署一个或多个中间 CA 证书。

中间 CA 再用它们自己的私钥来签署最终的用户证书。

这种分层结构的好处是，如果一个中间 CA 的私钥被泄露，只需撤销该中间 CA 的证书，而无需撤销整个根 CA 的信任，从而限制了损害范围。

##### 实体证书 / 叶子证书 (End-Entity Certificate / Leaf Certificate):

这是最终颁发给服务器（如网站）、个人或设备的证书。它由一个中间 CA 签名。

#### 验证信任链

当你的浏览器（或其他客户端）访问一个使用了 SSL/TLS 的网站时，它会收到一个包含网站证书的证书链（通常是实体证书 + 一个或多个中间证书）。浏览器会执行以下验证步骤：

##### 检查实体证书的有效性
1. 检查证书是否过期
1. 检查证书的通用名称 (CN) 是否与访问的域名匹配
1. 检查证书是否被撤销（通过 CRL (Certificate Revocation List) 或 OCSP (Online Certificate Status Protocol)）

##### 验证签名
1. 浏览器使用上一级证书的公钥来验证当前证书的数字签名
1. 这个过程会一直向上追溯，直到找到一个由浏览器本身预装的根 CA 证书
1. 如果整个链条上的所有签名都能成功验证，并且最终追溯到了一个受信任的根 CA，那么这个网站的证书就被认为是可信的

#### 证书类型

##### 自签名证书（测试环境常用）

自己生成 CA 和证书，适用于测试、内网、开发用途。

##### 受信任机构签发的证书（正式生产环境）

向 CA（如 Let's Encrypt、DigiCert、GlobalSign）申请证书。

##### Java 证书（JKS / keystore 格式）

用 keytool 工具生成，适合 Tomcat、SpringBoot 等。

#### 示例

##### 生成自签名证书
 ```

# 1. 生成私钥
openssl genrsa -out server.key 2048

# 2. 生成证书签署请求 (CSR)
openssl req -new -key server.key -out server.csr

# 3. 自签发证书，有效期 365天
openssl x509 -req -in server.csr -signkey server.key -out server.crt -days 365

# 4. 查看证书内容
 openssl x509 -in server.crt -noout -text
```

##### Java 证书
 ```
keytool -genkeypair \
 -alias mycert \
 -keyalg RSA \
 -keysize 2048 \
 -validity 365 \
 -keystore mykeystore.jks
```

##### 免费证书

Let's Encrypt 是一个由互联网安全研究小组（ISRG）运营的证书颁发机构（CA），它提供了一个自动化的流程来生成和更新证书，使得网站管理员可以轻松地为他们的站点启用 HTTPS 加密。

Certbot 是一个开源的自动化工具，用于获取和续订由 Let's Encrypt 提供的免费 SSL/TLS 证书：
- 自动化：它可以自动验证域名所有权，并申请证书
- 免费：它使用的是 Let's Encrypt 提供的免费证书
- 兼容性：支持多种 web 服务器，如 Apache、Nginx 等
- 易用性：提供了命令行界面，使得安装和使用变得简单
- 续订：自动处理证书的续订，确保网站的 HTTPS 连接始终保持有效

Let's Encrypt 颁发的证书有效期为 90 天，Certbot 会自动配置证书的续期任务，确保证书不会过期。

[SSL 免费证书申请 - Certbot](https://www.runoob.com/http/ssl-certbot.html)
 ```

# apt install certbot

# 证书路径: /etc/letsencrypt/live/yourdomain.com/
certbot certonly --standalone -d yourdomain.com
```
